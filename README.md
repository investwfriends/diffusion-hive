## 🚀 Quick start (pick up where we left off)

**What this is:** a Hive (surround-the-queen) board-game AI. A **3,120,540-param block-diffusion transformer** (`HiveLiteModel`: hidden 128, 6 layers, policy MLP head + value head + aux heads) trained by supervised imitation of the **native Mzinga C# engine** (negamax depth 4, driven over UHP).

**Result: the model beats random** (~11–17.5% win / ~0–5% loss / rest draws, vs random's 0% win / 100% draw). Not decisive: the policy head (15.7% top-1 vs teacher) is the bottleneck and 8 interventions (scaling, MLP head, value lookahead, plan-conditioned diffusion, MCTS, diffusion decoding, policy fine-tune, self-play policy iteration) all plateau at 12–17% win. The strong teacher itself only wins 37.5% vs random (62.5% draws). Full story: `paper/paper.md` + `paper/figures/`.

**Best model:** `runs/plan_run/final_model.pt` (plus `best_model.pt`, `metrics.jsonl`).

- `sp_data.pt` (2,402 self-play visit-distribution samples)

# DiffusionHive

A Hive-board-game AI that trains a lightweight block-diffusion
policy/value model (`HiveLiteModel`, ~589K params) using strong teacher
data generated by the native **Mzinga C# engine** via the Universal Hive
Protocol (UHP).

## Why this exists

The original approach used an in-repo AlphaZero model as the teacher for
data generation. It performed poorly (win rate vs random ~7-22% after
72K steps). The fix: replace the AlphaZero teacher with the **real
Mzinga engine** — a negamax + quiescence search with transposition
tables and learned metric weights — driven over UHP via a subprocess.
This gives dramatically stronger, more decisive training data.

## Architecture

```
Mzinga C# engine (teacher)
        │  UHP subprocess (stdin/stdout)
        ▼
MzingaUHPAdapter  ──►  gen_data.py  ──►  dataset.pt
                          (blend:            │
                           50% vs random,    │  LiteTrainingSample[]
                           50% self-play)    ▼
                                       pipeline.py (train → eval → self-play)
                                          │
                                          ▼
                                    HiveLiteModel
                                    (~589K params)
```

## Quickstart (macOS, Apple Silicon)

### 1. Install Mzinga (Python engine + venv)

```bash
cd Mzinga
uv sync --extra gym          # installs torch + gymnasium + dev deps
uv run python scripts/build_mypyc.py   # optional: 2.5-3x speedup, ~30s
uv run pytest                # 104 tests should pass
cd ..
```

### 2. Verify the UHP teacher works

```bash
PYTHONPATH="Mzinga/src:." Mzinga/.venv/bin/python -c "
from mzinga.core.board import Board
from mzinga.core.enums import GameType
from ghive_diffusion_lite.mzinga_uhp_adapter import MzingaUHPAdapter
a = MzingaUHPAdapter(depth=3, sample=False)
label, play, val = a.evaluate(Board(GameType.Base))
print(f'teacher: label={label} value={val:+.3f}')
a.close()
"
```

### 3. Generate training data (UHP teacher, blend mode)

```bash
PYTHONPATH="Mzinga/src:." Mzinga/.venv/bin/python -m ghive_diffusion_lite.gen_data \
    --games 400 --workers 5 --output dataset.pt \
    --teacher uhp --uhp-depth 3 --random-fraction 0.5
```

This produces a blend of:
- **50% teacher vs random** — the model learns to punish weak play
- **50% teacher self-play** — the model learns strong strategy

Each worker spawns its own `MzingaEngine` subprocess. The teacher's
negamax score (from `ReportIntermediateBestMoves`) is squashed to
`[-1, +1]` via `tanh(score/20000)` as the value target; terminal
outcomes override this via backfill.

### 4. Train the model

```bash
PYTHONPATH="Mzinga/src:." Mzinga/.venv/bin/python -m ghive_diffusion_lite.pipeline \
    --dataset data/dataset_200k.pt --device cpu --out-dir runs/my_run \
    --steps 20000 --batch-size 16 --lr 3e-4 --num-workers 4 --skip-selfplay
```

Training is **batched** (since 2026-07-29): `--steps` counts optimizer
steps, so steps/epoch = n_samples / `--batch-size` (default 16).
Defaults are play-focused: `--diffusion-weight 0.1`,
`--value-weight 1.0`, `--self-condition-prob 0.0`. CPU and MPS are
equally fast for this 589K model; prefer CPU so parallel eval workers
don't contend with MPS. The pipeline runs train → eval → self-play
with periodic checkpoints and best-model selection by eval win rate
(skip self-play — it still uses the legacy AlphaZero teacher).

## Key flags for `gen_data.py`

| Flag | Default | Purpose |
|---|---|---|
| `--teacher uhp\|alphazero` | `uhp` | Teacher source. `uhp` = native C# engine (strong, default). `alphazero` = in-repo model (legacy). |
| `--uhp-depth N` | `4` | Search depth for the UHP engine. 3-5 is a good range. Higher = stronger but slower. |
| `--uhp-epsilon E` | `0.05` | Epsilon-greedy exploration rate for play moves. |
| `--random-fraction F` | `0.5` | Blend: fraction of games vs random (rest are self-play). `0.0` = pure self-play, `1.0` = pure vs random. |
| `--opponent random\|teacher` | `random` | Legacy binary mode (used when `--random-fraction` is not set). |
| `--counterfactual` | `True` | Query teacher for labels on every ply, not just its own turns. |
| `--scramble-plies N` | `6` | Play N random opening plies before teacher evaluation. |
| `--games N` | `1000` | Total games to generate. |
| `--workers N` | auto | Parallel workers (auto from CPU/RAM). |
| `--shard-bytes B` | `0` | Rotate streaming shards of this size (e.g. `104857600` = 100MB). |
| `--target-bytes B` | `0` | Stop once total shard bytes reach this. |

## Training history (kept runs)

| Run | Steps | Win rate vs random | Notes |
|---|---|---|---|
| `lite_standard_run_cpu` | 2,000 | 20% | Early baseline, full pipeline |
| `lite_value_v2` | 2,000 | — | Value-head experiment |
| `lite_enriched_50k` | 32,000 | — | Enriched dataset experiment |
| `lite_run1` | 72,000 | 7.5% | Longest run (more steps ≠ better with weak teacher) |
| `lite_run_merged_mps_full` | 6,500 | 20% | Most complete pipeline run (train + eval + self-play) |
| `lite_run_dagger_fast_parallel_eval` | 3,500 | 22.5% | Best dagger result |

The poor win rates (max 22.5%) motivated switching from the AlphaZero
teacher to the UHP teacher. The UHP teacher produces stronger, more
decisive data — retrain on UHP-generated data for better results.

## Cloud VM workflow

For large generation runs on a Linux cloud VM:

```bash
# On your Mac: package the repo
bash pack_for_cloud.sh
# Upload DiffusionHive_cloud.zip to the VM

# On the VM: setup (installs Python, torch, Mzinga, downloads Linux engine)
cd /DiffusionHive && bash setup_cloud.sh

# Generate data (UHP teacher auto-downloads the Linux binary)
PYTHONPATH="$PWD:$PWD/Mzinga/src" \
nohup python3.12 -u -m ghive_diffusion_lite.gen_data \
    --games 400 --uhp-depth 3 --random-fraction 0.5 \
    --output /DiffusionHive/dataset.pt \
    --report-interval 60 > gen.log 2>&1 &
```
